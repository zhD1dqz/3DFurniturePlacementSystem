最新成功实验：`results/20261101_175731_312302/phone-report.json`。

该次采样记录的最高进程 PSS 约 **241 MB**，最高电池温度 **33.9 ℃**，Android 热状态最大值 **0**。这是一次约 76 秒测试，不能说明长时间连续扫描的温升或 GPU 总显存。PSS、原生堆分配和 GPU 设备内存不是同一指标。脚本总观察/取回耗时约 81 秒；75.78 秒是原生引擎从初始化到评估及模型导出的墙钟时间，不包含开发安装和首次素材解包。

查看 `results/20261101_175731_312302/evaluation/` 中五个实际手机渲染视角。它们由同一次拍摄选出的评估视图产生，相机与初始稀疏点仍来自电脑，不能视为完整手机采集的独立泛化测试。

## 重要限制与诊断

- **固定数量优化已验证；增密未通过。** 首次增密前 6006 个参数全部有限；新增高斯的一部分随后出现 NaN。一次诊断中 170 个新增高斯的几何和高阶 SH 字段异常，旧高斯没有该类异常。
- 将优化器 epsilon 从 1e-15 改为 1e-8 未解决增密问题，因此不把这一修改描述为修复完成。当前兼容路径保留经实测的 epsilon=1e-8，并关闭增密；首个正式手机训练参数尚未定案。
- 当前还不能归因于具体 GPU 驱动、零初始化或单个内核。进一步定位应检查增密后的优化器状态与张量操作，或评估更新版引擎的相关修复；不能仅凭这次结果断言手机性能不足。
- 引擎 loss 包含负的 SSIM 奖励项，负 loss 本身不是异常。非有限数值才触发本实验的错误检测。
- 修正了采样配置：Brush 先 `take(max_frames)` 再 `step_by(subsample_frames)`，所以只设置 max_frames=32 和间隔3并非覆盖全视频的32张。最新实验不截断原100帧，按间隔3保留34视图，并选出5视图评估。
- 还未实现手机内同步采集、手机位姿恢复/验证、自动家具分割、动态模型加载或新模型到 AR 的直接交接。当前模型包含原场景背景。
- 测试程序无网络权限，仅在手机执行本地计算；这不表示首次应用安装、AR 服务准备或后续所有功能均已通过离线验收。

## 三分钟预算

用户要求一次手机训练不超过三分钟。本测试在原生循环墙钟约 150 秒后准备提前导出，另在 Android 界面设 180 秒独立终止保护，防止计算卡住时无限运行。当前成功实验未触发该阈值；阈值触发、恢复和后台状态尚未完整实测。

180 秒看门狗在此开发程序中会终止本测试进程，保留已保存的检查点。正式 App 应将计算放在独立工作进程并支持停止、恢复与保留界面，这属于后续流程整合工作。这个保护不改动原 AR App。

## 构建与运行（由开发侧处理）

```powershell
& 'D:/Python/python.exe' mobile-reconstruction/prepare_probe.py
& 'D:/Python/python.exe' mobile-reconstruction/build_probe.py
& 'D:/Python/python.exe' mobile-reconstruction/run_probe.py --steps 1200 --disable-refinement
```

第三条使用已经验证的固定数量模式。未加 `--disable-refinement` 的 300/1200 步命令是未通过的增密诊断路径，不作为推荐生成模式。直接在手机测试程序点「生成测试 · 最多三分钟」默认使用固定数量模式；由命令行启动后重用的诊断配置会沿用该次 Intent，重新从桌面打开可恢复默认入口。

`prepare_probe.py` 对原100张图像及3个COLMAP文件逐一校验并打包；`build_probe.py` 编译原生库与 Java 包装、签名并校验；`run_probe.py` 只安装独立包、读取该包自己的结果与日志，检查 PLY 结构、全部参数有限性、旋转有效性和原始文件哈希，保存进程内存与温度记录。

当前测试 APK 约 64 MB，包含约22 MB测试数据及尚未做体积裁剪的引擎依赖。不能以该大小宣称正式 App 的大小，也不把移除素材后的体积直接当作最终安装占用。
